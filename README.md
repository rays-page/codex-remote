# Codex Remote

`Codex Remote` is a two-part self-hosted control surface for Codex:

- a lightweight Windows launcher that stages the official Codex CLI runtime and exposes its websocket `app-server`
- a native iPhone client that connects to that websocket and gives you a focused remote session UI with the courier-pod companion persona

The design goal is simple: leave a Codex-capable desktop running, step away, and keep steering threads from your phone without remoting into the whole machine.

## What Is In This Repo

- `desktop/`
  - `codex_remote_desktop.py`: launcher, runtime staging, pairing-link generation, background start/stop/status
  - `start_codex_remote.bat`: one-click start entrypoint for a desktop shortcut
  - `stop_codex_remote.bat`: one-click stop entrypoint
  - `install_shortcut.ps1`: creates a `Codex Remote` shortcut on the Windows desktop
  - `tests/`: unit tests for the launcher logic
- `ios/CodexRemote/`
  - SwiftUI iPhone app that connects to the Codex websocket app-server
- `docs/`
  - setup and security notes

## How It Works

`Codex Remote` does not pretend to be Codex. It wraps the official local Codex runtime.

1. The desktop launcher finds the installed Codex app package.
2. It stages the bundled runtime into `%LOCALAPPDATA%\CodexRemote\runtime`.
3. It generates a capability token and starts `codex.exe app-server` in the background.
4. The iPhone app connects over websocket with `Authorization: Bearer <token>`.
5. The app drives the real Codex thread lifecycle: `thread/start`, `thread/list`, `thread/read`, `turn/start`, and `turn/interrupt`.

## Desktop Quick Start

From PowerShell in this repo:

```powershell
.\desktop\start_codex_remote.bat
```

Then install the shortcut:

```powershell
powershell -ExecutionPolicy Bypass -File .\desktop\install_shortcut.ps1
```

Useful commands:

```powershell
py -3 .\desktop\codex_remote_desktop.py status
py -3 .\desktop\codex_remote_desktop.py pairing
.\desktop\stop_codex_remote.bat
py -3 .\desktop\codex_remote_desktop.py doctor
py -3 -m unittest discover -s .\desktop\tests -v
```

## iPhone Client

Open `ios/CodexRemote/CodexRemote.xcodeproj` on a Mac in Xcode. The app expects:

- websocket URL, for example `ws://192.168.1.50:8765`
- capability token generated by the desktop launcher
- optional default workspace path
- optional default model and sandbox preference

The app also accepts a pairing deep link in this format:

```text
codexremote://pair?url=ws%3A%2F%2F192.168.1.50%3A8765&token=YOUR_TOKEN
```

## Remote Access Outside Your LAN

The desktop launcher exposes a websocket service. For true away-from-home use, put that websocket behind something you control, for example:

- Tailscale
- Cloudflare Tunnel
- your own reverse proxy with TLS and auth

When you have a public websocket URL, set it in the launcher so the pairing output uses the correct address:

```powershell
python .\desktop\codex_remote_desktop.py launch --public-ws-url wss://your-host.example/ws
```

## Security Notes

- The launcher uses a randomly generated capability token.
- The iPhone app sends that token as a bearer token.
- Cleartext `ws://` is enabled in the iOS app because this is a self-hosted tool. Use `wss://` if you expose it beyond your local network.
- The mobile client can start real Codex turns. Treat the token like a password.
